# EasyMacBord 动作与场景需求总结

**版本：** v0.2 T05，开发中；逻辑、界面与实体观察待验收
**载体：** EasyMacBord macOS 26+ 客户端的配置档、动作库与设备与同步页面
**设计方向：** 以 EasyInput 的实体键盘和旋钮为主信息面，不使用渐变背景或泛化玻璃装饰。

## 背景

用户已有多个配置档和本机动作，但在进入不同工作应用时需要手动切换。T05 在现有配置档上增加前台应用规则：用户为某个配置档选择已发现的本机应用，应用切到前台时，EasyMacBord 选择对应配置档，并在条件满足时安排同步。

同时，Maker 已定义可读取的设备状态与语义动作字段。Mac 端只在完整、匹配且已校验的状态响应后展示固件能力和可映射的设备语义动作。灯光和音乐律动没有当前设备控制合同，保持不可用。

## 用户使用方式

- 用户在配置档页打开“自动切换”，从本机应用列表选择一个带 Bundle ID 的应用，并将它与当前配置档关联。相同应用只能有一条启用的规则，避免前台切换结果不确定。
- 用户切换到匹配应用后，应用先选中对应配置档。设备已连接、本地保存完成且没有同步进行时，等待 750 ms 再发送当前配置；任一条件不满足时只切换本地选择，不伪造同步成功。
- 用户在动作库直接登记内建组合键预设：剪切 `Meta+X`、删除 `Backspace`、回车 `Return`、聚焦搜索 `Meta+Space`、切换输入法 `Ctrl+Space`。预设映射到控制件时写入值快照，后续修改预设不回写既有配置。
- 用户创建喝水提醒时选择 1 至 1440 分钟的间隔，默认 30 分钟。创建动作不改变通知状态；只有该动作实际被执行并得到系统结果后，权限页才显示通知已授权或调用失败。
- 用户触发“清洁屏幕遮罩”后看到黑色全屏遮罩，可用“关闭”或 Escape 退出。它不拦截物理键盘，也不读取屏幕内容。
- 用户触发“清空废纸篓”后必须在当前 Mac 的确认框中再次确认；确认才请求 Finder 清空废纸篓，取消不执行。
- 用户在设备与同步页点击“读取设备状态”。按钮只在 USB 已连接时可用；无完整有效回包时保持“未读取”或显示失败原因。
- 用户在映射检查器选择“设备语义动作”时，只有 `capabilities.semantic_actions=true` 的已校验状态才会显示通用语义动作；语音和编辑按住说话还要求已读取 `ptt_hotkey` 与 `edit_ptt_hotkey`。否则显示“设备未确认”，不可映射。

## 信息架构

1. **配置档页：** 当前配置档、8 键与旋钮、同步入口，以及“自动切换”规则管理入口。
2. **动作库：** 本机动作、输入预设、五个内建组合键预设、喝水提醒与其他系统工具的登记、测试和删除。
3. **设备与同步：** 连接通道、状态读取按钮、已校验的设备字段、语音/编辑热键、保存确认与失败摘要。
4. **权限：** 辅助功能、自动化和通知。通知只由喝水提醒的实际执行结果更新。

## 范围与关键规则

- `ProfileActivationRule` 本地保存配置档 ID、应用 Bundle ID、应用名称和启用状态；不保存应用路径或安全书签。规则管理 UI 支持添加、启停和移除。
- 前台应用切换由 `ProfileSwitchCoordinator` 处理：只匹配启用规则和仍存在的配置档；自动切换关闭时不处理；切换到当前配置档时不重复发送。
- 自动同步只由前台应用规则触发，固定 750 ms 防抖。条件为设备已连接、配置档本地保存完成、当前没有同步；使用既有 USB 优先、失败不跨通道回退和 `0x03` 保存确认规则。
- 设备语义动作使用 Maker 已有的 `voice_ptt_hold`、`edit_ptt_hold`、`select_all`、`copy`、`paste`、`undo` 配置值，不是 Host Action UUID，也不调用 Mac 本机动作。
- 状态读取复用既有 Status HID v1：USB Feature Report `0x13 / S3R v1` 请求，`0x11 / kind 0x04` 分片响应。必须校验 request ID、分片、长度、CRC16 与 schema `ai_keyboard.config_status.v1`。
- “清空废纸篓”是破坏性 Finder 操作，必须本机确认。它与移除本地动作、预设或自动切换规则是两类不同操作；后者只影响 EasyMacBord 的本地登记。
- 关于页检查公开 GitHub Releases：正式包忽略预发布，Beta 包包含预发布；只显示 Release 信息、`arm64` DMG 与 SHA-256 外部链接。应用不下载、安装、替换或启动新版本。

## 不做

- 不修改 Maker 固件、GPIO、HID/GATT 描述符、Flash 分区、VID/PID、S3C v1、Host Action UUID 或 USB 优先规则。
- 不把音频诊断、Music 播放状态或界面动画当成板端灯光或音乐律动控制。
- 不新增自动更新、后台下载、差分更新或应用自替换。
- 不将前台应用规则扩展为日历、位置、网络、云端账户或跨设备触发。

## 数据与隐私边界

| 对象 | 本地保存 | 设备端保存 | 边界 |
|---|---|---|---|
| 自动切换规则 | 配置档 ID、Bundle ID、应用名称、启用状态 | 无 | 不保存应用绝对路径或安全书签；相同应用不允许多条启用规则 |
| 内建组合键预设 | 标题、组合键值 | 映射后的既有配置字段 | 登记后可复用；控制件保存快照而非预设引用 |
| 喝水提醒 | 登记动作的间隔值 | `host_action:<uuid>` | 通知权限和状态只在动作实际执行时处理 |
| 设备语义动作 | 既有动作原始值 | 既有配置字段 | 仅在已校验设备状态允许时可映射，不产生 UUID |
| 状态快照 | 已校验的公开字段与读取时间 | 无 | 不保存原始 HID 报文、request ID、MAC、序列号或未经校验 JSON |

## 状态与失败反馈

| 情况 | 界面反馈 | 系统行为 |
|---|---|---|
| 前台应用无匹配规则 | 保持当前配置档 | 不切换、不安排同步 |
| 自动切换关闭或设备未连接 | “已切换本地配置，待设备可用” | 不发送配置 |
| 同一应用存在重复启用规则 | “该应用已有自动切换规则” | 拒绝新增或启用重复规则 |
| 设备状态未确认 | “设备未确认” | 不提供设备语义动作映射 |
| PTT 字段缺失 | “设备未确认” | 语音、编辑按住说话不可映射；其他已声明语义动作按各自条件处理 |
| 喝水提醒间隔越界 | “提醒间隔需在 1 到 1440 分钟之间” | 不登记动作 |
| 通知未授权或安排失败 | 权限页显示“调用失败” | 不把动作登记或通知请求当成已授权 |
| 清洁屏幕遮罩 | 黑色遮罩与关闭控件 | 不禁止物理键盘，不读屏幕 |
| 清空废纸篓 | “确认清空废纸篓” | 取消不执行；确认才请求 Finder 操作 |

## 验收边界

- 自动切换规则、750 ms 防抖、内建预设、提醒间隔、通知状态、遮罩、废纸篓确认和语义动作门控需要逻辑测试与 UI 验收。
- `1280 x 800` 与 `1120 x 720` 的截图只证明布局和状态可见，不证明通知、Finder、状态回包或实体按键实际生效。
- 状态读取、M-01 至 M-08 本机工具验证、`0x03` 保存确认和 HW-01 至 HW-07 真机矩阵分别记录，任一未执行项保持 `UNKNOWN`。
