# 构建与发布

## 前置条件

必须安装与当前系统匹配的完整 Xcode，并将其设为活动开发目录。仅安装 Command Line Tools 时，`xcodebuild`、资源工具和 Swift SDK 可能与系统 SDK 不匹配，不能据此报告构建通过。

构建前检查：

```bash
xcodebuild -version
xcrun --sdk macosx --show-sdk-version
swift --version
```

## 测试与构建

```bash
swift test
scripts/package-app.sh 0.1.0-beta.2
```

`package-app.sh` 固定使用 `--arch arm64`。每次打包会先执行 `swift test`，再生成 `dist/EasyMacBord.app`、DMG、同名 `.sha256` 摘要和同名 `.manifest.json`。构建成功、签名成功、同步确认和真机功能成功是四种不同证据，发布记录必须分开写。

manifest 是候选包的机器可读记录，包含版本、Git 提交 SHA、工作树状态、Xcode/Swift 版本、通过的测试数量、架构、DMG 文件名与 SHA-256，以及签名标识、签名类型、Team Identifier 和包格式。它不记录本机绝对路径、设备标识、用户信息、证书或 Keychain 内容。

内部 Beta 候选包必须由 `source_tree_state` 为 `clean` 的工作树生成；`dirty` manifest 只可用于本地诊断，不可作为发布候选。校验文件只写入 DMG 文件名和 SHA-256，便于在其他目录中复核：

```bash
shasum -a 256 -c dist/EasyMacBord-0.1.0-beta.2-arm64.dmg.sha256
swift -e 'import Foundation; let data = FileHandle.standardInput.readDataToEndOfFile(); _ = try JSONSerialization.jsonObject(with: data); print("manifest JSON valid")' < dist/EasyMacBord-0.1.0-beta.2-arm64.dmg.manifest.json
```

## ad-hoc 签名

脚本使用：

```bash
codesign --force --sign - EasyMacBord.app
codesign --verify --strict EasyMacBord.app
```

`-` 表示 ad-hoc 签名。脚本会将必要的签名字段写入 manifest，不保存 `codesign --display` 的绝对路径输出。产物没有 Team Identifier、Developer ID、时间戳或 Apple 公证。不要使用 Xcode 自动签名，也不要把个人证书、描述文件或 Keychain 内容提交到仓库。

## 分发

DMG 面向小范围测试。测试者将应用拖入“应用程序”后，如 Gatekeeper 阻止首次打开，可在“系统设置 → 隐私与安全性”手动确认打开。不要承诺陌生设备无提示安装。

GitHub Actions 仅运行源码测试。最终 DMG 必须在 Apple Silicon 本机生成并保留签名校验输出的脱敏摘要。
