# 构建与发布

## 前置条件

必须安装与当前系统匹配的完整 Xcode，并将其设为活动开发目录。仅安装 Command Line Tools 时，`xcodebuild`、资源工具和 Swift SDK 可能与系统 SDK 不匹配，不能据此报告构建通过。

构建前检查：

```bash
xcodebuild -version
xcrun --sdk macosx --show-sdk-version
swift --version
```

## 测试与构建

```bash
swift test
scripts/package-app.sh 0.1.0-beta.1
```

`package-app.sh` 固定使用 `--arch arm64`，生成 `dist/EasyMacBord.app`、DMG 与同名 `.sha256` 摘要。构建成功、签名成功、同步确认和真机功能成功是四种不同证据，发布记录必须分开写。

## ad-hoc 签名

脚本使用：

```bash
codesign --force --sign - EasyMacBord.app
codesign --verify --strict --verbose=2 EasyMacBord.app
codesign --display --verbose=4 EasyMacBord.app
```

`-` 表示 ad-hoc 签名。产物没有 Team Identifier、Developer ID、时间戳或 Apple 公证。不要使用 Xcode 自动签名，也不要把个人证书、描述文件或 Keychain 内容提交到仓库。

## 分发

DMG 面向小范围测试。测试者将应用拖入“应用程序”后，如 Gatekeeper 阻止首次打开，可在“系统设置 → 隐私与安全性”手动确认打开。不要承诺陌生设备无提示安装。

GitHub Actions 仅运行源码测试。最终 DMG 必须在 Apple Silicon 本机生成并保留签名校验输出的脱敏摘要。
