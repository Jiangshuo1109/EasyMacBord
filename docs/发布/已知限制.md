# 已知限制

- 当前构建基线为 Xcode 27.0 beta 6。正式版 Xcode 发布后，应使用正式工具链再次完成构建、测试和 DMG 签名验证。
- ad-hoc 签名只封存代码，不提供 Developer ID 身份、公证或跨机器无提示安装保证。
- USB Status HID 已在兼容设备上完成一次只读联调；配置写入保存确认、BLE 配置服务/特征、实体输入与 Host Action 尚未完成实机验收。
- v0.1 不包含 AI、语音、Wi-Fi 音频、灯光控制、音乐律动、DDC、自动更新和云同步。
- T03 的应用目录读取和本机工具已通过单元测试、arm64 Release 编译和内部 DMG 签名校验；尚未取得新包的人工界面截图，M-01 至 M-08 也尚未形成实际观察结论。
- T04 的 Dock 窗口恢复、独立动作库、输入预设、组合键录制、宏键盘界面、设置与关于已实现并通过逻辑测试、arm64 Release 构建与内部打包。当前只保留默认 `1280 x 800` 发布包总览截图；Dock 重新打开、`1120 x 720`、本机工具和真机验收仍未形成实际结论。
- 应用目录仅用于让用户选择本机应用；未选择的候选项不保存，已选择应用移动或失效后必须重新选择。
- “保持唤醒”只防止闲置显示器休眠；不保证合盖继续运行，不替代系统锁屏，也不保证阻止所有系统休眠原因。
- 打开系统截图与录屏界面不等于已生成截图或录屏文件。应用不直接读取屏幕内容。
- 当前版本不提供应用内屏幕采集或录制，因此不会仅为打开系统截图面板请求“屏幕录制”权限；该权限会在未来接入 ScreenCaptureKit 时重新评估。
- 壁纸只接受用户主动选择的图片；测试会改变桌面背景，需由测试人员自行恢复。
- 音量控制只针对当前默认输出，输出设备不支持相应控制时应失败。隐藏应用不会退出应用，也不会改动 Dock 或 Finder 设置。
- Apple Music 控制仅支持播放/暂停、上一首和下一首，取决于 Music 是否可用及系统自动化权限；不支持其他播放器，也不把命令提交当作播放成功。
- 组合键录制只支持项目协议已覆盖的常见键位和修饰键。全局监听、仅修饰键、Fn、媒体键及未映射键位不作为可保存组合键。
- 关闭菜单栏显示后，应用仍应通过 Dock 或应用菜单恢复主窗口；开机启动状态受系统“登录项”设置约束，应用不会将需要系统确认的状态显示为已启用。
- 深色模式、屏保、键盘清洁、隐藏桌面文件、隐藏 Dock、分屏、显示器亮度和键盘亮度仅通过用户维护的 macOS 快捷指令接入。项目不写入私有偏好，也不调用私有显示器接口。
- T05 的前台应用自动切换、状态读取和自动同步已完成代码实现。USB 状态读取已通过既有 `0x13 / S3R v1` 与 `0x11 / kind 0x04` 合同的完整只读校验；M-01 至 M-08、真实前台应用切换、BLE 配置、保存确认和实体输入仍待验收。没有有效状态响应时不推断语义动作能力或 PTT 热键。
- Maker 状态 JSON 中的音频诊断不能证明板端灯光、音频播放控制或音乐律动存在。没有新增并冻结的设备控制合同前，相关入口应显示 `UNKNOWN / 不可用`。
- “检查更新”只读取公开 GitHub Releases：正式包忽略预发布，Beta 包包含预发布；只显示 Release 信息、`arm64` DMG 与其 SHA-256 外部链接。ad-hoc 构建不支持应用内下载、自动替换、自动安装或自动启动；用户必须在默认浏览器中自行取得包并按 Gatekeeper 提示处理。
- 更新检查不要求 GitHub 账号或访问令牌。Release 说明和链接只用于当次界面显示，不应写入本地配置、常规日志、诊断记录或截图证据。
- 前台应用规则只保存配置档 ID、应用 Bundle ID、应用名称和启用状态，不保存应用路径或安全书签。移除规则、动作或输入预设只影响 EasyMacBord 本地登记。
- 清空系统废纸篓是独立的 Finder 操作，必须在当前 Mac 的确认框中再次确认；取消不执行，确认也不意味着 Finder 一定成功。清洁屏幕遮罩不读取屏幕内容，也不禁止物理键盘输入。
- 喝水提醒的间隔范围是 1 至 1440 分钟，默认 30 分钟。通知状态只在该动作实际执行后按系统结果更新；登记提醒不代表已获通知授权。
- GitHub 已通过 SSH 同步；仍应在每次发布后核对远端提交与本地提交一致。
