# EasyMacBord 软件需求规格说明书

**版本：** v0.1
**目标读者：** 产品负责人、macOS 开发人员、EasyInput 固件维护人员和真机测试人员

## 1. 背景与目标

EasyInput V2.0 已能通过 USB HID 或 BLE HID 输出普通键盘事件，并可发送 Host Action UUID。日常使用中，用户需要在 Mac 上维护多个按键配置档，并把“打开应用”等本机动作绑定到实体控制件。现有硬件不应持有应用路径、应用名称或启动参数。

v0.1 的目标是提供一个可安装的 Apple Silicon macOS 工具：用户可查看连接状态、编辑一套日常配置、同步到设备，并在设备返回合法 UUID 时执行已在本机登记的动作。

## 2. 范围

### 2.1 本版包含

| 编号 | 需求 | 验收条件 |
|---|---|---|
| FR-01 | 菜单栏显示设备状态和当前配置档 | 未连接、查找中、USB、BLE 四种状态可区分 |
| FR-02 | 管理配置档 | 至少能显示、选择和编辑一套配置档 |
| FR-03 | 编辑 KEY1-KEY8 与旋钮左/右/按下 | 每个控制件都能设置本机动作、固定文本、键盘组合键或禁用 |
| FR-04 | 生成设备配置 | 输出 `ai_keyboard.v1` JSON，包含 8 键和旋钮的完整字段 |
| FR-05 | USB/BLE 配置同步 | USB 可写时优先 USB；无 USB 时才使用 BLE；USB 失败不改走 BLE |
| FR-06 | 只在确认后显示成功 | 回执必须满足 phase=1、ok=true、saved=true、bytes/CRC 匹配 |
| FR-07 | 执行本机动作 | 仅对规范小写 UUID 查找本地登记项；映射不存在时不执行 |
| FR-08 | 处理权限 | 展示辅助功能、屏幕录制、自动化的当前状态或按需检查状态 |

### 2.2 明确不包含

- AI 对话、总结、翻译、TTS、板端录音和 Wi-Fi 音频。
- 音乐律动、外接显示器 DDC、自动更新、远程账户同步。
- 修改 Maker 固件、烧录、改变 GPIO、BOOT、GPIO8 电源、分区、HID/GATT 描述符或设备身份。
- 未经用户设置的应用启动、自动化或屏幕录制。

## 3. 主要场景

### 3.1 配置并同步一个本机动作

用户在“配置档”中选择 KEY1，选择“本机动作”，登记一个目标应用。EasyMacBord 为该动作保存 UUID 到本机应用安全书签的映射，并向设备配置写入 `host_action:<uuid>`。同步仅在设备确认相同内容已保存后结束。

### 3.2 按下实体按键

设备按下后发送 `0x11 / kind 0x05`。应用先确认 USB 是当前优先事件通道，再检查 UUID 是否为 36 位小写规范形式。查到映射后才调用本机执行器；松开事件和格式错误消息不触发动作。

### 3.3 权限不足

若动作需要辅助功能或屏幕录制，界面显示“需要授权”，不伪造成功。用户完成系统授权后可重新检查并重试该动作。

## 4. 非功能要求

- **平台：** 最低 macOS 26，`arm64`；不支持 Intel。
- **界面：** 使用系统导航、工具栏、材料与 SF Symbols；玻璃效果仅用于设备状态等高优先级内容。
- **安全：** 设备端只保存动作 UUID；本机路径以安全书签保存；常规日志不记录 UUID、路径、用户文本或设备唯一标识。
- **可靠性：** 配置不以“已发送”判定成功；非法协议 fail closed；双通道不重复执行。
- **可访问性：** 所有关键按钮有名称；窄窗口下按键卡片换行，不依赖纯颜色区分状态。

## 5. 失败处理

| 情况 | 界面反馈 | 系统行为 |
|---|---|---|
| 无设备 | “未建立可写入通道” | 不发送配置 |
| USB 写入失败 | “USB 写入失败” | 不自动改走 BLE |
| 回执长度或 CRC 不一致 | “设备未确认保存” | 保留原同步状态，不执行新动作 |
| UUID 非规范格式 | “设备消息格式无效” | 不查询映射、不执行 |
| 目标应用已移动 | “应用位置已变更，请重新选择” | 不启动替代目标 |

## 6. 发布要求

应用使用 ad-hoc 签名，TeamIdentifier 为空；不使用 Developer ID，不公证。发布包为 DMG，并在发布说明中写明 Gatekeeper 的手动放行限制。
