# 测试计划

## 证据层级

| 层级 | 证明什么 | 不能证明什么 |
|---|---|---|
| 单元测试 | 编码、路由、确认和本地数据逻辑 | 设备实际收发 |
| 应用构建 | arm64 应用可被工具链编译 | 签名、真机功能 |
| 配置确认 | 设备保存了同一份 JSON | 物理按键和本机动作 |
| 真机验收 | 实体输入的实际结果 | 以后版本持续兼容 |

## 自动化测试

1. CRC 向量、1/52/53/2048/2049 字节边界、分片头和 CRC。
2. `0x03` 确认的成功、错误分片头、saved=false、bytes 不同、CRC 不同，以及 8 秒无确认超时。
3. `0x05` 的小写 UUID、大小写错误、长度错误、前缀错误；`0x04` 不执行动作。
4. KEY1-KEY8 与旋钮的完整 JSON 序列化，固定文本、热键、Host Action 与禁用状态。
5. USB 优先、USB 失败不回退、USB 缺失时 BLE 可用。
6. ProfileStore 版本化读写、v0 裸数组迁移和初始配置；Host Action 的登记、恢复和缺失映射失败。
7. BLE 多分片逐帧回调后发送、写入失败和中断。该项依赖可注入的 CoreBluetooth 适配器，当前仅保留真机前的实现检查。

## UI 检查

- 状态总览：未连接、连接中、USB、BLE、同步中、同步失败、同步确认。
- 配置档：无配置、只配置一个键、长文本、窄窗口下的按键卡片。
- 权限：已授权、拒绝、按需检查。

## 真机矩阵

只有收到同一份配置的保存确认后才可开始。每项单独记录条件、用户观察、时间、结果和失败层。

| 编号 | 项目 | 通过条件 |
|---|---|---|
| HW-01 | USB-only | 配置确认成功，按键触发目标动作 |
| HW-02 | BLE-only | 配置确认成功，按键触发目标动作 |
| HW-03 | 双连接 | 同一按键只执行一次 |
| HW-04 | 按下 | 单次按下只产生一次动作 |
| HW-05 | 松开 | 松开不重复触发 |
| HW-06 | 回归 | 复制、粘贴、快捷键、固定文本仍正常 |
| HW-07 | 本机应用 | 已选目标应用实际打开 |

任一项目未执行即为 `UNKNOWN`，不能用其余项目替代。
