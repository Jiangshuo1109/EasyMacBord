# 架构与协议

## 1. 模块边界

| 模块 | 职责 | 不承担 |
|---|---|---|
| `DeviceProtocol` | S3C 分帧、CRC、`0x11` 解码 | 设备发现、动作执行 |
| `DeviceTransport` | USB/蓝牙配置通道写入、活动通道路由 | 用户配置和应用路径 |
| `ProfileStore` | 本地配置档 JSON | 设备端 NVS 持久化 |
| `InstalledApplicationCatalog` | 只读枚举常规应用程序目录、去重并提供候选项 | 保存未被用户选择的应用、向设备发送应用路径 |
| `HostActionRegistry` | UUID 到本机动作、安全书签 | 向设备发送路径或 Bundle ID |
| `HostActionPresentation` | 从已登记目标运行时解析图标和显示信息 | 持久化应用图标、公开安全书签或绝对路径 |
| `InputPresetStore` | 保存固定文本、录制组合键和内建组合键预设 | 向设备发送预设 UUID、反向改写既有控制件 |
| `SyncHistoryStore` | 上次有效确认与最近同步失败摘要 | 伪造设备状态或替代真机确认 |
| `PermissionCenter` | 辅助功能、自动化和通知的实际结果状态 | 绕过系统权限或把动作登记当作授权 |
| `ActionExecutor` | 打开已授权目标、网址、快捷指令和登记的直接系统工具 | 未登记的任意命令执行、私有系统设置修改 |
| `MainWindowCoordinator` | 统一处理菜单栏、Dock 和应用重新激活时的主窗口恢复 | 创建多份主窗口或替代系统窗口生命周期 |
| `AppPreferences` | 菜单栏显示、登录项状态与包版本信息 | 自动启用登录项或伪造系统授权 |
| `DeviceStatusReader`（T05） | 仅在 USB 已连接时发送既有 Status HID v1 请求、重组并校验 `0x04` 状态 JSON | 改写设备状态、猜测能力或代替保存确认 |
| `ProfileActivationStore`（T05） | 保存配置档与前台应用 Bundle ID 的自动切换规则 | 保存应用路径/安全书签或写入设备 |
| `ProfileSwitchCoordinator`（T05） | 接收前台应用变化，选择匹配配置档并在条件满足时以 750 ms 防抖安排同步 | 同步未保存配置、并发写入、绕过 USB 优先或确认回执 |
| `WaterReminderScheduler`（T05） | 在喝水提醒动作实际执行时请求并安排系统通知 | 在动作登记时伪造通知授权或保存通知内容 |
| `GitHubReleaseChecker`（T05） | 读取公开 GitHub Releases；正式包忽略预发布、Beta 包包含预发布；识别 Release 信息、`arm64` DMG 与对应 SHA-256 外部链接，并交由默认浏览器打开 | 下载、安装、替换或自动启动应用 |

数据流为：`实体输入 → HID Input → DeviceProtocol → HostActionRegistry → ActionExecutor → ExecutionRecord`。配置方向为：`Profile → FirmwareProfileSerializer → DeviceProtocol S3C frame → USB 或蓝牙配置通道 → 确认回执 → SyncHistoryStore`。T03 的应用目录扫描和系统工具均位于 Mac 本地动作链路，不参与设备协议、配置帧或通道路由。

## 2. 冻结的设备消费者合同

### 配置写入

- HID Report ID：`0x10`，USB 为 Feature Report。
- 帧格式：`S3C`、版本 `1`、chunk index、chunk total、总长度 LE、分片长度、CRC16-CCITT LE、分片数据。
- 单片数据上限：52 字节；完整 JSON：1 至 2048 字节；必须严格顺序发送。
- CRC：初值 `0xffff`，多项式 `0x1021`，不反射、无最终异或；`123456789` 的结果为 `0x29b1`。

### 保存确认

设备通过 `0x11` Input 返回 63 字节 App Command：`[0...3] = 03 00 01 07`；数据区依次为 phase、ok、bytes LE、crc16 LE、saved。只有 `phase=1`、`ok=1`、`saved=1` 且 bytes/CRC 与本次 JSON 完全一致时，应用才显示“已确认”。`0x04` 仅为状态响应，不得作为确认或动作。

### Host Action

`0x11 / kind 0x05 / chunk 0/1 / len 36`。数据区只放无 `host_action:` 前缀的 36 字节小写 canonical UUID ASCII；大写、长度错误、非法字符、前缀或非单分片一律拒绝。设备不保存应用路径、名称、Bundle ID、图标或启动参数。

## 3. 通道路由

USB 可用时是唯一优先通道。配置写入失败直接报告失败，不迁移到蓝牙配置通道。USB 不存在时，蓝牙配置通道使用自定义配置 GATT：

- Service：`7D2F4D10-6F6B-4A2D-8B01-6D4653320001`
- Write：`...0002`
- Status：`...0003`

Host Action 统一从 HID Input 处理；双连接时只接受当前活动通道的事件。蓝牙配置通道 Status JSON 仅消费 `phase`、`bytes`、`crc16`、`saved` 等确认字段。

配置写入路由与输入事件路由相互独立。macOS IOKit 可能将 BLE HID 报告为 `Bluetooth` 或 `Bluetooth Low Energy`，两者都归一化为 BLE HID。USB HID 存在时只接收 USB 输入；USB 不存在时接收已枚举的 BLE HID 输入，不以自定义配置 GATT 是否可写作为前提。

### T05 复用的状态读取合同

T05 不增加状态协议。主机用既有 HID Feature Report `0x13` 发送 16 字节 `S3R` v1 请求：3 字节 magic、版本 `1`、非零 request ID（LE）、flags（可使用 fresh）和零保留字节。设备使用既有 `0x11 / kind 0x04` 返回 63 字节分片容器：chunk index、chunk total、data length、协议版本、request ID、完整 JSON 总长度、CRC16 和分片 JSON。Mac 端必须在当前 request ID 下按序重组，验证版本、chunk total、长度和 CRC 后，才解码 `ai_keyboard.config_status.v1`。

状态读取与 `0x03` 保存确认、`0x05` Host Action 相互独立。`0x04` 的 status JSON 可以包含 firmware、saved、bytes、crc16、电池、音频诊断、capabilities、`ptt_hotkey` 与 `edit_ptt_hotkey`；T05 只消费已有字段。只有 `capabilities.semantic_actions=true` 才显示通用设备语义动作；语音和编辑按住说话分别要求对应 PTT 字段已读取。字段缺失、schema 未知或校验失败时保持 `unknown`，不写入设备、不显示推测能力，也不将音频指标解释为灯光或音乐律动控制。

## 4. 本地数据与隐私

配置档使用应用支持目录的版本化 JSON。应用目录扫描只读取用户、本地和系统应用程序目录，候选项只在内存中存在；按 Bundle ID 去重，并在缺失 Bundle ID 时以候选位置区分。用户从列表确认的应用才通过安全书签写入动作库，映射与设备配置分开保存。应用图标从已登记目标在运行时解析，既不写入设备配置，也不作为图像数据持久化。`InputPresetStore` 以版本化本地 JSON 保存标题、类型和值；选择预设时将值复制至控制件，控制件不保存预设引用。固定文本和组合键因其功能本身必须保存在配置或预设文件中，但不写入常规日志、执行记录、截图证据或诊断输出。同步历史只保存上一次满足确认条件的时间和回执摘要，以及最近一次失败原因；失败不清除上一次确认。应用日志和本机动作记录只保存可公开的结果分类与动作显示名，不记录 UUID、绝对路径、完整 MAC、序列号或 USB 拓扑。

T05 的 `ProfileActivationStore` 仅保存配置档 ID、应用 Bundle ID、应用名称和启用状态；应用路径和安全书签继续由动作库单独管理，自动切换规则不读取或复制它们。相同应用不得有多条启用规则。状态快照只保存已校验的公开摘要与读取时间，不保存原始 HID 报文、request ID、设备唯一标识或未经校验的 JSON。移除规则、动作或预设只影响本地登记；清空系统废纸篓必须由当前 Mac 的确认框放行后才交给 Finder，不触及设备端数据。

## 5. T03 本机工具边界

`HostActionTarget.kind == system` 仍使用既有 UUID 注册表。设备侧仍只收到 `host_action:<uuid>`；系统工具标识、用户选择的壁纸安全书签、应用安全书签以及快捷指令名称都不写入 S3C JSON 或设备端。

| 类型 | 本机执行方式 | 明确边界 |
|---|---|---|
| 应用 | `NSWorkspace` 打开用户从本机目录列表中确认的应用 | 只在选择后持久化安全书签；目标失效时要求重新选择 |
| 截图与录屏 | 打开系统“截图”界面 | 不直接开始截图或录屏，不自行读取屏幕内容 |
| 锁定屏幕 | 调用现有锁屏路径 | 手动测试保留二次确认 |
| 保持唤醒 | 创建防止闲置显示器休眠的电源断言 | 不保证合盖继续运行，不保证阻止系统锁定或所有休眠原因 |
| 壁纸 | 使用用户选择图片的安全书签设置桌面背景 | 不扫描照片库，不自动更换壁纸 |
| 音量 | 控制当前默认音频输出的音量或静音 | 输出设备不支持时失败；不修改其他设备 |
| 隐藏应用 | 隐藏当前前台应用 | 不终止应用，不修改 Dock 或 Finder 偏好 |
| Apple Music | 通过系统自动化请求播放/暂停、上一首或下一首 | 仅面向 Apple Music；是否可用受自动化权限、Music 状态和系统返回结果约束 |
| 清洁屏幕遮罩 | 显示可用关闭按钮或 Escape 退出的黑色覆盖层 | 不读取屏幕内容，不拦截物理键盘 |
| 喝水提醒 | 动作实际执行时请求并安排周期通知 | 间隔范围 1 至 1440 分钟；登记动作不改变通知状态 |
| 清空废纸篓 | 经当前 Mac 确认后请求 Finder 清空系统废纸篓 | 取消不执行；不静默清空 |
| 整理桌面 | 请求 Finder 整理桌面图标 | 受 Finder 自动化授权和系统返回结果约束 |
| 快捷指令模板 | 运行用户登记的 macOS 快捷指令 | 深色模式、屏保、键盘清洁、隐藏桌面文件/Dock、分屏、显示器/键盘亮度均不内置实现 |

## 6. UI 状态模型边界

- `MainWindowCoordinator` 是菜单栏命令、Dock 重新打开和应用重新激活的唯一主窗口入口。它恢复已有窗口或显示一个主窗口，不以调用来源创建重复窗口。
- 根界面提供状态总览、配置档、动作库、设备与同步、权限；设置和关于位于侧栏底部。窗口工具栏保留页面名称，内容区不重复显示同一标题。侧栏顶部固定显示 EasyMacBord 品牌与独立的设备连接摘要。
- 配置档编辑区以 8 个固定尺寸键帽和一枚旋钮呈现 11 个控制事件。动作名称截断不改变键帽、旋钮选择区或检查器布局；已登记应用可在键帽上显示运行时解析的图标。
- 动作库同时管理 Host Action 和输入预设。应用、网址、快捷指令、直接系统工具继续通过 `HostActionRegistry` 注册 UUID；固定文本和组合键预设不进入 UUID 注册表，选择时仅将快照写入 `ActionBinding`。内建组合键预设固定为剪切、删除、回车、聚焦搜索和切换输入法，使用既有规范组合键格式。
- 组合键录制控件只在用户明确开始录制后接收当前窗口的按键事件，并把支持的键转换为既有序列化语法。它不使用全局键盘监听，也不记录用户在其他应用中的输入。
- `DeviceDetails` 的固件版本、备用通道、能力和 PTT 热键只来自已校验的设备状态。当前未收到对应状态帧时必须为 `unknown`，界面统一显示“未读取”。
- `SyncHistory` 的确认记录只能在收到完整匹配的保存回执后写入；任意发送错误、超时或不匹配只追加失败摘要。该历史是本地 UI 证据，不能证明设备当前仍保存该配置。
- `ExecutionRecord` 仅由 Host Action 的设备触发结果和手动测试结果写入。固定文本与键盘组合键由实体设备执行，应用没有可靠的完成回执，因此不生成执行成功记录。
- 动作库的应用选择器只显示应用名称、图标和来源，不显示绝对路径。直接系统工具和快捷指令模板必须先登记为本机动作，才可以映射到 11 个控制事件。
- 系统截图界面打开、Apple Music 命令发送和快捷指令进程启动只代表本机已完成相应请求；除非系统提供可确认结果，不能据此推断截图文件、音频播放或目标业务动作已完成。
- 辅助功能权限只在用户明确请求时触发系统提示，并在应用恢复激活时重新检查。自动化没有统一的全局预检；其页面状态来自首次相关动作的系统结果。通知也没有预先标记为已授权，只有喝水提醒实际执行的结果才能更新它。由于本期没有应用内屏幕采集功能，权限页不包含屏幕录制项。
- Debug 构建允许通过 `--ui-state` 载入固定截图状态；状态解析和样例数据被 `#if DEBUG` 包围，Release 不提供此入口，也不跳过任何设备或权限检查。
- T05 的配置档页面提供前台应用自动切换规则。规则命中后只选择既有配置档。`semantic_actions=true` 时才显示设备语义动作；语音与编辑按住说话分别要求对应 PTT 字段已读取。语义动作写入 Maker 既有值，不走 `host_action:<uuid>`。
- T05 自动同步由前台应用规则驱动：匹配规则后等待 750 ms，且设备已连接、配置已保存、没有同步进行时才调用既有同步路径。立即同步取消等待并发送当前版本一次；确认语义仍由现有保存回执决定。
