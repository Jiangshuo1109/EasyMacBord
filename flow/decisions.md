# 决策记录

## 2026-08-26 · v0.1 使用 macOS 26+ 原生界面

- **决定：** 使用 SwiftUI/AppKit 和系统材料，最低版本设为 macOS 26，产物只支持 arm64。
- **原因：** 项目明确需要当前 macOS 的玻璃质感，且首批用户是 Apple Silicon 环境。
- **影响：** 不为 macOS 15 及更早版本提供降级界面。

## 2026-08-26 · 设备配置与本机映射分离

- **决定：** 设备端只接收 `host_action:<uuid>`；应用目标、安全书签和执行方式只保存在 Mac 本地。
- **原因：** 设备不应携带用户应用路径、名称、Bundle ID 或启动参数。
- **影响：** UUID 无本地映射时必须停止执行并提示用户。

## 2026-08-26 · 同步确认以设备回执为准

- **决定：** 只有 `0x11/kind=0x03` 或对应蓝牙配置通道 Status 的长度和 CRC 与本次 JSON 匹配时，才显示“已确认”。
- **原因：** “已发送”不能说明设备已持久化配置。
- **影响：** USB 写入失败不自动转蓝牙配置通道；出现不匹配时保留失败证据。

## 2026-08-26 · v0.1 使用 ad-hoc 分发

- **决定：** 使用 `codesign -s -` 打包 DMG，不使用 Developer ID 或公证。
- **原因：** 当前是私有小范围测试，不引入开发团队或证书管理。
- **影响：** 发布说明必须告知 Gatekeeper 手动放行限制。

## 2026-08-26 · 主窗口采用四页导航与三栏配置编辑

- **决定：** 主导航固定为状态总览、配置档、设备与同步、权限。本机动作从独立页面移入配置档右侧检查器；配置页使用主侧栏、顶部配置档选择器、控制事件编辑区、设置检查器三栏。
- **原因：** 动作登记只有在绑定某个控制件时才需要，独立页面让配置路径来回跳转，且把 UUID 等实现细节暴露为用户任务。
- **影响：** 8 个按键和单枚旋钮左转、按下、右转共 11 个事件在一个编辑区内维护；界面不显示 UUID、安全书签或绝对路径。

## 2026-08-26 · 手动测试只覆盖可由应用执行的本机动作

- **决定：** 测试入口仅对已登记的本机动作开放。固定文本和键盘组合键必须通过实体设备验证；锁定屏幕等影响当前会话的动作需二次确认。
- **原因：** 应用无法可靠确认实体设备向目标上下文发送的文本或组合键是否生效，直接标记成功会误导用户。
- **影响：** 动作记录只接收 Host Action 和手动测试的结果，不将固定文本或组合键写为“已执行”。

## 2026-08-26 · 蓝牙仅称为配置通道，未知设备信息显式标注

- **决定：** 文档和界面统一使用“蓝牙配置通道”，不再沿用暗示蓝牙输入用途的命名。没有状态读取协议时，固件版本、备用通道和能力统一显示“未读取”。
- **原因：** 当前蓝牙链路的职责是写入配置和接收确认，不足以证明 HID 输入能力或设备详情。
- **影响：** 不为 UI 增加协议字段；未来接入状态帧时再将字段从“未读取”切换为已读取值。

## 2026-08-26 · 同步失败保留上次有效确认

- **决定：** 本地保存最后一次完整匹配的确认时间与回执摘要。发送失败、超时或回执不匹配只记录本次失败，不能覆盖最后一次有效确认。
- **原因：** 用户需要区分“当前尝试失败”和“此前已有确认”，但不能据此推断设备当前仍保有该配置。
- **影响：** 设备与同步页同时呈现上次确认和本次失败；同步历史属于本地 UI 证据，不替代真机验证。

## 2026-08-26 · 截图状态仅在 Debug 构建存在

- **决定：** 通过 `--ui-state <名称>` 提供可复现的 Debug 截图状态，Release 构建不编译解析器和样例数据。
- **原因：** 界面验收需要稳定地覆盖失败、长名称和权限不足状态，但不能使用真实设备、个人配置或本机动作数据。
- **影响：** 截图证据必须标注为 Debug 验收，不得作为设备连接、权限授予或动作执行的证据。

## 2026-08-26 · 本地保存采用单调版本拒绝旧快照

- **决定：** 配置档、动作库和同步历史每次保存携带单调递增版本号；持久层忽略比已接收版本更旧的写入。
- **原因：** 连续编辑会并发创建保存任务，任务到达 actor 的顺序不能作为用户编辑顺序。
- **影响：** 无论旧任务何时完成，重新读取本地数据都保留最后一次编辑的快照。

## 2026-08-27 · 本机应用只能由用户确认后登记

- **决定：** 动作库可只读扫描用户、本地和系统应用程序目录中的 `.app`，但候选项只保留在内存中。应用列表不展示绝对路径；只有用户选择后才为该目标创建安全书签并登记为 Host Action。
- **原因：** 用户需要从当前 Mac 的已安装应用中选择目标，同时不能把整台机器的应用清单、路径或未使用目标写入本地动作库或日志。
- **影响：** 扫描失败时可改用手动选择；已登记应用移动或失效时要求重新选择，不根据名称猜测替代项。

## 2026-08-27 · 系统工具分为直接动作和用户快捷指令

- **决定：** 直接实现系统截图与录屏界面、锁定屏幕、仅防止闲置显示器休眠、用户选图壁纸、默认输出音量、隐藏前台应用及 Apple Music 的播放/暂停、上一首、下一首。深色模式、屏保、键盘清洁、隐藏桌面文件、隐藏 Dock、分屏、显示器亮度和键盘亮度统一经用户自行配置的 macOS 快捷指令接入。
- **原因：** 前一组可在明确边界内使用公开系统能力完成；后一组涉及用户工作环境、显示器能力或 Finder/Dock 设置，不应以私有接口或写偏好文件的方式实现。
- **影响：** 每项工具仍先登记为本地 Host Action，再映射到控制件。快捷指令模板只提供预填名称，不创建或修改用户快捷指令。Apple Music 操作依赖系统自动化权限；保持唤醒不承诺合盖继续运行或阻止系统锁定。

## 2026-08-27 · T03 不改变设备消费者合同

- **决定：** T03 只扩展 Mac 本地动作目录与执行器，不修改 Maker 固件、GPIO、HID/GATT 描述符、S3C v1 配置帧、Host Action UUID 格式或 USB 优先规则。
- **原因：** 应用选择和系统工具不需要设备端保存路径或新增协议字段。
- **影响：** 新动作在设备侧仍表现为既有 `host_action:<uuid>`；T03 的本机工具测试与 HW-01 至 HW-07 分开记录，不能替代保存确认或实体输入证据。

## 2026-08-27 · T04 采用独立动作库与输入预设快照

- **决定：** 将动作维护设为独立侧栏页面。应用、网址、快捷指令和直接系统工具继续登记为 Host Action；固定文本与组合键使用独立本地预设，应用预设时将当前标题和值复制给控制件。
- **原因：** 动作可在未选择某个控制件时整理，固定文本和组合键又不能改为 `host_action:<uuid>` 而不改变设备合同。快照可避免编辑预设后意外修改已同步控制件。
- **影响：** 预设不进入 UUID 注册表，不改变 S3C JSON。应用图标仅从已登记的安全书签目标在运行时解析，不写入持久化数据或设备端。

## 2026-08-27 · T04 统一主窗口入口并将权限与实际能力对齐

- **决定：** 菜单栏、Dock 和应用重新激活共用主窗口恢复协调器。菜单栏显示默认开启，登录项默认关闭。权限页仅保留辅助功能和自动化；辅助功能由用户主动请求，自动化按首次执行结果显示。
- **原因：** 主窗口不应依赖菜单栏入口存在。现有截图与录屏动作只打开系统截图面板，不读取屏幕内容，申请或展示屏幕录制权限会制造错误预期。
- **影响：** 关闭菜单栏后仍可由 Dock 恢复。屏幕录制权限将在未来应用内采集功能引入时单独设计和验收；T04 的设计或逻辑测试不改变任何硬件门禁结论。
